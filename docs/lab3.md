## 준비

Lab 2까지 만든 `비용 처리 담당 (본인 이름)` 을 그대로 씁니다. Skill이 붙어 있는 상태입니다.

---

## 단계

### A. 켜기 전에 물어봅니다

1. **새 대화**를 시작합니다.

2. 아래를 그대로 입력합니다.

    ```
    제가 비용 처리할 때 어떤 걸 먼저 확인해 달라고 했는지 기억하세요?
    ```

3. 답을 읽습니다. **모른다**고 답합니다.

    ![촬영: 모른다고 답한 화면](../assets/lab3/lab3-01.png)

4. 당연한 답입니다. 앞 랩에서 그런 말을 한 적이 없고, 대화가 바뀌면 맥락도 사라집니다.

### B. 메모리를 켭니다

{: start="5" }
5. 에이전트 설정에서 **메모리** 토글을 켭니다.

    ![촬영: 메모리 토글](../assets/lab3/lab3-02.png)

6. **저장**을 선택합니다.

7. **새 대화**를 시작합니다.

### C. 업무 맥락을 남깁니다

{: start="8" }
8. 아래를 **그대로** 입력합니다. 한 글자도 바꾸지 않습니다.

    ```
    법인카드 비용을 처리할 때 프로젝트 비용이면 프로젝트 코드를 먼저 확인해줘.
    ```

    {: .warning }
    **문장을 바꾸지 마세요.** 사람마다 다른 문장을 쓰면 결과가 달라져 완료 판정이 되지 않습니다.

9. 답을 읽습니다. 기억했다고 말합니다.

    ![촬영: 기억했다는 응답](../assets/lab3/lab3-03.png)

10. 화면에 도구 호출이 붙었는지 봅니다. **파일을 쓴 것입니다.** 말로만 받아 둔 것이 아닙니다.

11. **새 대화**를 시작합니다.

     {: .important }
     같은 대화에서 확인하면 안 됩니다. 같은 대화에서 되묻는 것은 대화 맥락만으로도 됩니다. **Memory가 일하는지는 새 대화에서만 확인됩니다.**

12. 파일 두 개를 첨부하고 아래를 입력합니다.

     ```
     이번 달 비용 정산 정리해 주세요.
     ```

13. 답을 봅니다. 정리해 주기 전에 **먼저 되물어야** 합니다.

     ![촬영: 프로젝트 코드를 되묻는 화면](../assets/lab3/lab3-04.png)

     {: .important }
     **여기가 이 랩의 판정입니다.** 바로 정리를 시작하면 실패입니다.

14. 어떻게 알았는지 물어봅니다.

     ```
     그건 어떻게 알고 계셨나요?
     ```

15. 답을 읽습니다. 기억해 둔 것을 봤다고 말합니다.

### D. 무엇이 올라갔는지 봅니다

{: start="16" }
16. 아래를 그대로 입력합니다.

     ```
     지금 저에 대해 기억하고 있는 것의 목록을 보여주세요.
     ```

17. 답을 읽습니다. **한 줄짜리 색인**입니다. 내용 전체가 아닙니다.

     ![촬영: 기억 색인](../assets/lab3/lab3-05.png)

18. 하나를 열어 보게 합니다.

     ```
     그중 하나의 실제 내용을 열어서 보여주세요.
     ```

19. 답을 읽습니다. **이번에는 도구를 호출합니다.** 16번에는 없던 것입니다.

     ![촬영: 본문을 열어 본 화면](../assets/lab3/lab3-06.png)

20. 둘의 차이를 봅니다.

     | | 어디에 있나 | 언제 읽나 |
     |---|---|---|
     | 색인 한 줄 | 대화 시작 때 **항상** 실린다 | 늘 |
     | 본문 | 파일로 남아 있다 | 필요할 때 **열어서** |

     {: .note }
     기억이 백 개로 늘어도 대화에 실리는 것은 색인 백 줄입니다. 본문은 안 실립니다. 대신 색인에 없는 것은 **찾지 못합니다.** 파일만 있고 색인에 안 오르면 없는 것과 같습니다.

### E. 에이전트 화면을 훑습니다

{: start="21" }
21. 왼쪽 편집 화면으로 돌아갑니다. 오늘 만진 자리를 한 번에 봅니다.

     ![촬영: 에이전트 편집 화면 전체](../assets/lab3/lab3-07.png)

22. 오른쪽 패널이 무엇을 담는 자리인지 짚어 봅니다.

     | 자리 | 무엇이 들어가나 | 오늘 넣은 것 |
     |---|---|---|
     | Model | 어느 모델로 도나 | `Claude Sonnet 5` |
     | Channels | **어디서 이 에이전트를 만나나** | 아직 없음. F단에서 붙입니다 |
     | Skills | 이 일을 하는 방식 | `expense-reconcile` |
     | Tools | 바깥 시스템에 손을 뻗는 자리 | 없음 |
     | Knowledge | 회사가 아는 것 | `비용처리규정.docx` |
     | Connected agents | 다른 에이전트와 나눠 맡는 자리 | 없음 |
     | Memory | 이 사용자의 맥락 | 프로젝트 코드를 먼저 |

     {: .note }
     지침(Instructions)은 오른쪽이 아니라 **가운데 본문**입니다. 오늘 가장 먼저 쓴 자리입니다.

23. 위쪽 탭을 봅니다. **Build · Preview · Evaluate · Monitor** 넷입니다.

     ![촬영: 상단 탭](../assets/lab3/lab3-08.png)

24. **Monitor**가 **회색으로 눌리지 않는 것**을 확인합니다. 게시하지 않은 에이전트는 쌓인 기록이 없습니다.

     {: .note }
     **Evaluate**는 만든 것이 의도대로 답하는지 시험해 두는 자리입니다. 오늘은 열어만 봅니다.

### F. 채널에 붙이고 게시합니다

{: start="25" }
25. 오른쪽 **Channels**의 **+**를 선택합니다.

     ![촬영: 채널 추가 대화상자](../assets/lab3/lab3-09.png)

     {: .note }
     고를 수 있는 것이 **`Teams + Microsoft 365`** 와 **`App`** 둘입니다. 표준 하네스보다 좁습니다.

26. **`Teams + Microsoft 365`** 를 고릅니다.

27. 사용 범위를 확인합니다. 기본값은 **M365 Copilot과 Teams 둘 다**입니다.

     ![촬영: 사용 범위 선택](../assets/lab3/lab3-10.png)

     {: .warning }
     **이 설정은 게시한 뒤에 바꿀 수 없습니다.** 화면에 그렇게 적혀 있습니다. 기본값 그대로 둡니다.

28. **Add channel**을 선택합니다. 오른쪽 Channels 아래에 칩이 하나 붙습니다.

29. **게시**를 선택합니다. 대화상자가 **어느 채널로 나가는지** 보여 줍니다.

     ![촬영: 게시 대화상자](../assets/lab3/lab3-11.png)

30. **Publish agent**를 선택합니다. 버튼이 `Publishing...` 으로 바뀝니다.

     {: .important }
     **채널이 붙은 게시는 몇 분 걸립니다.** 워크플로 게시가 10초대인 것과 다릅니다. 끝날 때까지 창을 닫지 않습니다.

31. Teams에서 만든 에이전트를 찾아 부릅니다.

32. 아래를 입력해 답이 오는지 봅니다.

     ```
     법인카드로 쓴 정기결제 구독료도 증빙 대장에 올려야 하나요?
     ```

     ![촬영: Teams에서 답한 화면](../assets/lab3/lab3-12.png)

     {: .important }
     **편집 화면 밖에서 답하면 통과입니다.** 지금까지는 미리 보기에서만 답했습니다.

     {: .note }
     게시는 Lab 4의 전제이기도 합니다. **워크플로의 에이전트 노드는 게시된 에이전트만 목록에 올립니다.**

## 랩의 결론

같은 문장처럼 보이는 둘이 서로 다른 자리에 들어갑니다.

| | 문장 | 어디에 |
|---|---|---|
| 회사의 규칙 | 프로젝트 비용에는 프로젝트 코드가 필요하다 | [Knowledge](./glossary.html#knowledge) 의 규정 §6.2 |
| 이 사람의 맥락 | 이 사용자는 프로젝트 코드를 **먼저** 확인받기를 선호한다 | [Memory](./glossary.html#memory) |

회사 규정을 Memory에 넣으면 사람마다 다른 규정을 갖게 됩니다. Knowledge의 영역입니다.

Memory의 성공 기준은 길지 않습니다.

> **기억한다 → 다음 업무에서 활용한다 → 필요한 정보를 먼저 되묻는다.**

그리고 게시하기 전까지 오늘 만든 것은 편집 화면 안에서만 살아 있었습니다. 게시가 그 경계를 넘습니다.
